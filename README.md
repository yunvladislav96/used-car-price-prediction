## Постановка задачи

### Бизнес-задача
Рынок автомобилей с пробегом в России — крупный и нестабильный сегмент,
где цена зависит от десятков факторов. Продавец часто не может адекватно
оценить свою машину и либо занижает цену (теряет деньги), либо завышает
(объявление висит месяцами). Покупатель, в свою очередь, не понимает,
справедлива ли цена.

### Цель проекта
Разработать ML-модель, которая по характеристикам автомобиля с пробегом
предсказывает его рыночную стоимость. Дополнительно — выявить ключевые
факторы, влияющие на цену, и объяснить их вклад.

### Ожидаемый результат
1. Обученная модель CatBoost с MAE в пределах 15–25% от медианной цены.
2. Интерпретация модели: какие признаки влияют на цену и как.
3. Функция `recommend_price`, возвращающая рекомендуемую цену продажи.
4. Сопроводительная документация: выводы по каждому этапу.

### Критерии успеха
- MAE ≤ 250 тыс. руб. (при медианной цене 1.1 млн) ✅ 233 тыс.
- R² ≥ 0.85 ✅ 0.964
- Модель не «чёрный ящик» — есть интерпретация через SHAP ✅
- Работает на реальных примерах: для массового сегмента отклонение близко к MAE, для отдельных машин может быть выше ✅

## Данные

**Источник:** парсинг объявлений с Drom.ru (4006 объявлений, 39 марок, 175 моделей).

**Сырые данные** (`data/raw/drom_cars_4000.csv`, 17 колонок):
`url`, `ad_id`, `марка_модель`, `цена`, `год`, `двигатель`, `мощность`,
`коробка`, `привод`, `цвет`, `пробег`, `владельцы`, `руль`, `поколение`,
`комплектация`, `город`, `кузов`.

**Обработанные данные** (`data/processed/cars_clean.csv`, 21 колонка):
исходные признаки + `объём`, `топливо`, `гбо`, `марка`, `модель`.
Удалён пустой `кузов`.

**Целевая переменная:** `цена` — медиана 1.11 млн руб., среднее 1.75 млн,
распределение скошено вправо.

## Этапы работы

### Этап 1. Сбор данных (`01_parsing.ipynb`)

Парсинг Drom.ru по заданным маркам и городам.
**Результат:** 4006 объявлений, 17 исходных колонок.

### Этап 2. EDA и предобработка (`02_EDA_final.ipynb`)

**Что сделано:**
- Первичный анализ: типы, пропуски, распределения.
- Очистка: удалён пустой `кузов`, исправлены аномалии пробега
  (< 100 км у старых, > 800 тыс км).
- Feature engineering: разбор `двигатель` на объём/топливо/ГБО,
  разбор `марка_модель` на марку и модель, унификация дублей
  (Лада/LADA, автомат/АКПП).
- Визуализации: распределения цены, корреляционная матрица,
  boxplot по маркам, scatter-plot цена vs пробег/мощность.

**Ключевые инсайты EDA:**
- Распределение цены скошено вправо (среднее > медианы в 1.6 раза) —
  это обосновывает использование MAE, а не RMSE.
- Сильнейшие корреляции с ценой: мощность (+0.67), год (+0.52),
  объём (+0.43), пробег (−0.40).
- Выбросы проверены вручную — это реальные машины
  (премиум, спорткары, старые LADA), а не ошибки данных.

**Статистический анализ (проверка гипотез):**

| Гипотеза | Тест | Результат | Вывод |
|---|---|---|---|
| Правый руль влияет на цену | t-тест Уэлча | p = 8.75e-15 | ✅ различие значимо (~490 тыс. руб.) |
| Привод связан с сегментом | χ²-тест | p = 2.75e-233 | ✅ 4WD чаще в среднем и премиум |
| Год коррелирует с ценой | Спирмен | ρ = 0.728 | ✅ положительная связь |
| Пробег коррелирует с ценой | Спирмен | ρ = −0.471 | ✅ отрицательная связь |

Отличие ρ Спирмена от r Пирсона для года (0.728 vs 0.52) показало,
что связь нелинейная — это обосновало выбор CatBoost вместо линейных моделей.

**Результат:** `cars_clean.csv` (4006 строк, 21 колонка).

### Этап 3. Построение ML-модели (`03_ML_model.ipynb`)

**Эксперименты:**

| Модель | MAE, руб. | RMSE, руб. | R² |
|---|---|---|---|
| Baseline CatBoost | 236 064 | 430 225 | 0.962 |
| **CatBoost + Optuna (лучшая)** | **233 200** | **420 350** | **0.964** |
| Лог-таргет | 252 454 | 484 162 | 0.952 |

**Почему CatBoost:**
- Нативная работа с категориальными признаками (10 колонок, включая
  `модель` с 175 значениями) — не нужно OneHot-кодирование.
- Устойчив к пропускам (не требует импутации).
- Хорошо ловит нелинейные зависимости и взаимодействия признаков.

**Подбор гиперпараметров:** Optuna (30 trials, 3-fold CV) дала улучшение
MAE на 1.2% относительно baseline (233 200 против 236 064 руб.). Прирост
небольшой — это говорит о том, что дефолтная конфигурация CatBoost уже
близка к оптимуму на данном датасете.

**Гипотеза лог-таргета:** проверена и отклонена (ухудшение по всем метрикам).

**Анализ ошибок по сегментам:**

| Сегмент | Средняя ошибка, руб. |
|---|---|
| до 1 млн | 114 825 |
| 1–3 млн | 240 371 |
| 3–10 млн | 545 149 |
| > 10 млн | 1 350 919 |

В процентах ошибка примерно одинаковая (~10–15%), абсолютная растёт
с ценой — это ожидаемо.

### Этап 4. Интерпретация модели (SHAP)

**Топ-5 признаков по вкладу в цену:**

| Признак | Вклад |
|---|---|
| год | ~540 тыс. руб. |
| мощность | ~270 тыс. руб. |
| модель | ~120 тыс. руб. |
| объём двигателя | ~100 тыс. руб. |
| пробег | ~90 тыс. руб. |

Направления влияния совпадают с экономическим смыслом и результатами
корреляционного анализа из EDA. Dependence plot показал нелинейную
зависимость: вклад года резко растёт после 2020, вклад мощности —
после 300 л.с.

**Результат:** модель не «чёрный ящик», её решения можно объяснить
пользователю.

### Два подхода к важности признаков

В проекте используются **два разных метода** оценки важности признаков, и их
результаты немного отличаются:

| Метод | Что измеряет | Единица измерения | Где применяется |
|---|---|---|---|
| **SHAP** | Средний вклад признака в прогноз | рубли | Анализ в `03_ML_model.ipynb` |
| **CatBoost feature importance** | Как часто и эффективно признак используется в деревьях | проценты | Дашборд `dashboard/app.py` |

**Топ-3 совпадают:** год выпуска, мощность и объём двигателя — главные
факторы по обоим методам.

**Различия в порядке** объясняются разной природой метрик:
- `модель` (175 категорий) в SHAP даёт большой рублёвый вклад, но в
  CatBoost «размазывается» по множеству сплитов — отсюда разное место
  в топе.
- `объём` — простая числовая колонка, компактно влияет на деревья,
  поэтому в CatBoost importance поднимается выше.

Оба подхода корректны и дополняют друг друга: SHAP показывает
**денежный вклад** признака, CatBoost importance — **структурную опору
модели**.

### Этап 5. Практическое применение

Функция `recommend_price` возвращает рекомендуемую цену по 16
характеристикам машины:

```python
recommend_price(
    марка='Тойота', модель='Камри', год=2016, мощность=181,
    пробег=142340, коробка='АКПП', привод='передний',
    топливо='Бензин', руль='левый', цвет='белый',
    город='Москва', поколение='8 поколение, рестайлинг',
    комплектация='2.5 AT Престиж', объём=2.5,
    владельцы=2.0, гбо=False
)
# → 2576912.47  (float, в рублях)
```

**Проверка на реальных машинах из датасета:**

| Машина | Прогноз | Реальность | Отклонение |
|---|---|---|---|
| Toyota Camry 2016 | 2 576 912 | 2 100 000 | +22.7% |
| Hyundai Creta 2020 | 1 822 772 | 1 795 000 | +1.5% |
| Kia Mohave 2021 | 4 293 264 | 5 000 000 | −14.1% |

## Ключевые выводы

1. **Основные факторы ценообразования:** год выпуска, мощность, модель.
   Связь с годом нелинейная — модель улавливает ускоренный рост цены
   после 2020.
2. **Модель корректно различает сегменты** (бюджет / средний / премиум).
3. **Точность выше в массовом сегменте** (MAE ~115 тыс. на авто до 1 млн),
   ниже — в премиуме (MAE ~1.35 млн на авто дороже 10 млн).
4. **Практическая ценность:** продавец получает ориентир с точностью
   ±20% от медианной цены. Для 85% рынка (бюджет + средний сегмент)
   точность выше.

## Ограничения

1. **Данные — цены предложения** Drom.ru, а не цены сделок. Реальные
   сделки могут быть ниже на 5–10%.
2. **Модель не работает на незнакомых сегментах** (спорткары, экзотика) —
   в обучающей выборке их мало.
3. **Для новых марок прогноз менее надёжен** — модель не видела их
   при обучении.
4. **Премиум-сегмент** (>10 млн) — основная зона ошибок, требуется
   отдельная модель или больше данных.
5. **Данные — срез** на момент парсинга, модель не учитывает динамику
   рынка во времени.

## Как запустить

### 1. Клонировать репозиторий

```bash
git clone https://github.com/<твой-ник>/<имя-репо>.git
cd <имя-репо>
```


### 2. Установить зависимости

```bash
pip install -r requirements.txt
```

### 3. Запустить ноутбуки по порядку

Откройте Jupyter Notebook или JupyterLab из корня проекта:

```bash
jupyter notebook
```

Затем запускайте ноутбуки строго по порядку:

1. `notebooks/01_parsing.ipynb` — парсинг данных.
2. `notebooks/02_EDA_final.ipynb` — EDA и предобработка.
3. `notebooks/03_ML_model.ipynb` — обучение модели.

> Полный прогон Optuna занимает около 5 часов на 8-ядерном CPU. Для быстрой проверки можно уменьшить число trials в соответствующей ячейке.

### 4. Запустить дашборд

В отдельном окне терминала (Anaconda Prompt) выполните:

```bash
cd dashboard
streamlit run app.py
```

Дашборд откроется в браузере по адресу `http://localhost:8501`.

Дашборд содержит:

- интерактивные графики зависимости цены от года и пробега;
- важность признаков модели;
- форму прогноза цены по характеристикам автомобиля.
